## Reproduced application defects and fixes

| Priority | Defect observed | Fix and evidence |
| --- | --- | --- |
| High | Mobile JSON endpoints read an entire stream before enforcing their 24,000-byte limit; a stalled stream could wait indefinitely. | Reuse the streamed parser with a 24,000-byte cap and 15-second deadline. Oversized streams cancel and return 413; stalled bodies cancel and return 408. Tests cover both through the mobile HTTP boundary. |
| High | A stalled 401 response body became a timeout instead of an authentication denial. | Handle 401/403 before body parsing and cancel the body. Existing session-expiry handling now receives the correct status. No HTML diagnostics are shown to users. |
| High | Mobile requests allowed automatic redirects, including redirects of private POST bodies. | Enforce manual redirects and omit cookies on the bearer-token API. Reject opaque/ordinary redirects without retrying the business request. Native builds explicitly use the installed Expo fetch transport, whose iOS and Android implementations disable redirect following in manual mode. Physical-device verification is still required. |
| High | A delayed secure-store read could restore credentials after logout; a pending token write could finish after erasure; an obsolete restore denial could erase a newer login. | Generation checks around restore/sign-in/signup; serialize credential writes and erasure; commit the in-memory session only after storage succeeds. Tests exercise all three interleavings, storage failure, and competing sign-ins. Remote revocation during offline/cancelled authentication is not guaranteed by these local tests. |
| High | Two simultaneous signups for the same email produced success plus an internal error (200/500 in service-level tests). | Keep the database uniqueness boundary and translate a confirmed competing account into 409. Regression confirms 200/409 and exactly one complete credentials record. This does not implement verified email or account recovery. |
| High | Equal creation timestamps could make session-cap cleanup immediately delete the token just issued; two of six test logins then returned 401. | Exclude the newly issued session when retaining the four other sessions. Regression forces timestamp ties, verifies every newly issued token at issuance, and verifies the five-session cap. Older sessions can still be intentionally evicted by later logins. |
| High | Authenticated password-change requests had no dedicated attempt limit. | Authenticate first and enforce five attempts per account per 15 minutes before password derivation. Regression verifies five invalid-current-password responses followed by 429. This does not replace edge-wide abuse controls or production hash-cost benchmarking. |
| Medium | Older mobile refresh responses overwrote newer snapshots or hid a just-saved appointment. Loading could also clear while another operation was pending. | Read-generation checks and invalidation on local appointment updates; count pending operations per session. Tests reproduce both stale-response orders and retain loading until the remaining operation finishes. |
| Medium | Availability and assistant requests bypassed the hook's session-expiry handler. | Route both through the shared operation boundary; a 401 now clears the session and private snapshot. Hook tests cover both endpoints. |
| Medium | Broken browser-origin configuration threw again inside the error handler. | Validate origin policy once, fail closed with a safe 503, do not execute the operation, and do not attach an allowed-origin header on configuration failure. Approved-origin application errors retain CORS. |
| Medium | Caller cancellation depended on the transport honoring abort and could instead be mislabeled as timeout. | Race explicit cancellation independently, reject already-aborted calls without sending them, and validate per-request timeout values. No automatic write retry was introduced. |
| Medium | Public DNS names starting with `fc`, `fd`, or `fea` were mistaken for private IPv6 addresses. | Restrict the IPv6 prefix check to colon-containing hostnames in both runtime and Expo configuration. Public-hostname and actual private-IPv6 tests cover both layers. This remains configuration validation, not DNS-rebinding protection. |
| Low | Content types beginning with `application/json` but not actually JSON were accepted. | Match the media type exactly while allowing parameters such as charset. Invalid types return 415. |

## Verification scope and limits

- Focused tests failed before the fixes for mobile request intake, origin failure handling, denial/cancellation handling, stale snapshots, credential races, simultaneous signup and session pruning. Subsequent focused checks passed.
- The backend security runner uses actual backend source and real migrations in isolated SQLite. Identity, scanner and object storage are mocked; this is not Cloudflare edge/load verification.
- Mobile tests use the actual hook/repository with mocked storage/native/network APIs. They do not verify Keychain/Keystore behavior on a physical phone.
- A source/docs pattern scan found no matches for the selected API-key/private-key formats. A tracked-file check found no `.env`, `.dev.vars`, or private credential files. This is not entropy scanning, complete Git-history review, external secret rotation, or proof that no secret exists anywhere.
- Windows temporary-directory rename failures initially prevented tests from starting. Test commands use an ignored workspace-local `.validation-tmp` directory. Windows also denied dependency directory junctions after folder permission was granted. Installs completed with pnpm's supported hoisted layout, selected only for these local commands with `PNPM_CONFIG_NODE_LINKER=hoisted`; no project-wide linker change or security-policy bypass was made. Cache/store paths were workspace-local. Use the same local setting for subsequent installs in this restricted environment, or verify a normal isolated install in CI.
- Fresh browser coverage in this continuation is limited to the rendered admin sign-in landing. Authenticated navigation, responsive layouts and complete interactive mobile journeys were not repeated in the browser; earlier browser evidence remains historical.
- Native iOS/Android permissions, accessibility/large text, hardware back/deep links, background/resume, real offline/slow-network behavior, real identity-provider revocation, and long-lived load/soak tests remain unverified in this run.
- The capstone paper and prototype were not re-extracted or visually compared in this continuation. No claim of complete requirement revalidation is made.
